## Verification Notes

**Approach (deviation from literal task wording, same intent).** Yarn 1 classic does not support version-qualified `resolutions` keys (`"pkg@range"` — Berry-only; verified: install errored `"^2.0.0@^2.3.2"`), and a bare-global pin collapses *all* majors of a package to one version (empirically reproduced: it forced minimatch→3.1.5, ajv→8.20.0, js-yaml→4.3.0 across every consumer, which breaks named-export / API-incompatible consumers — electron-builder's minimatch@9/10, eslint's ajv@6, istanbul's js-yaml@3 `safeLoad`). A full `yarn.lock` regeneration patches cleanly per-major but drifts the toolchain and broke the TS 4.9 build (`@types/node` 20→26 `ffi.d.ts`, webpack 5.105→5.108, `TS18046`). Final approach = **minimal churn**: single-major transitives pinned via bare-global `resolutions`; `serialize-javascript` forced v6→v7 (out-of-range HIGH); the seven collapse-prone multi-major packages (`ajv`, `brace-expansion`, `js-yaml`, `minimatch`, `picomatch`, `semver`, `undici`) patched by deleting only their stale `yarn.lock` entries so `yarn install` re-resolves each major line to its latest in-range version (all ≥ advisory floor). Result: every major line stays on its own major — no collapse — and the toolchain (webpack, `@types/node`) is byte-identical to the committed lock.

**Resolved versions (new yarn.lock, all ≥ patched floor):** @babel/traverse 7.29.7 (critical); @babel/core/helpers/runtime/plugin-transform-modules-systemjs 7.29.7; braces 3.0.3; form-data 4.0.6; cross-spawn 7.0.6; flatted 3.4.2; immutable 4.3.9; serialize-javascript 7.0.7; svgo 2.8.2; tmp 0.2.7; ws 8.21.0; micromatch 4.0.8; nanoid 3.3.15; postcss 8.5.16; protocol-buffers-schema 3.6.1; yaml 1.10.3; ajv 6.15.0 + 8.20.0; brace-expansion 1.1.15 + 2.1.1 + 5.0.6; js-yaml 3.15.0 + 4.3.0; minimatch 3.1.5 + 5.1.9 (+ 9.0.9, 10.2.5 untouched); picomatch 2.3.2 (+ 4.0.4 untouched); semver 6.3.1 + 7.8.5 (+ 5.7.2, 7.5.4, 7.7.4, 7.8.4 untouched); undici 6.27.0 + 7.28.0. **electron 41.7.2 unmoved.**
